# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:db:v2` 这一项，或调用 `resetModule(模块)`。
  （旧版的 `hydropower-plant-om:entries` 存档会在首次打开 v2 时自动迁移。）

## 检修工作票完工落库

机组检修模块（`overhaul`）不只是改状态显示，所有写入都落在 `src/api/overhaul-service.ts`：

- **生命周期**：待审批 → 已批准 → 检修中 → 已完工，流转边登记在 `modules.ts` 的 `transitions`
  里，正向只能逐档推进；回上一档只有「退回申报」「暂停退回」两个既定入口，已完工是终态。
- **办理完工**：检修状态、实际工期、验收人员、验收结论在同一个事务里一次性写入
  （`local-store.ts` 的 `commit`：先序列化落 localStorage，失败恢复内存快照，不留下半条记录），
  同时把处理结果 upsert 到技术供水值班台账。
- **二次完工**：终态票允许再次办理，只覆盖为最后一次验收数据，台账按票号更新、不新增条数。
- **单一数据源**：列表、详情面板、另存的工作票清单快照、技术供水页的台账入口都从同一份存储读；
  检修中机组台数由列表数据现算，完工即回落；概览页与列表条数同源对账。
- **历史回填**：按完工时间从早到晚处理，每张票处理完即写校验点（`lastTicketId`），
  中断后再执行从断点继续，只补缺项、不顶替已有值。缺项补录规则（裁决理由写进备注与补录记录）：
  - 缺实际工期 → 按计划工期等额回填（计划工期是办票批准的唯一可核工期依据）；
  - 缺验收人员 → 统一记「值班负责人（历史补签）」，不冒用真人姓名；
  - 缺验收结论 → 按当时规则版本、以计划/实际工期兑现率自动定级。
- **验收规则换版**：`src/data/conclusion-rules.ts` 维护 v1/v2 阈值，换版后全部已完工票按新版
  重算，旧结论保留当时等级并在备注中注明版本。
